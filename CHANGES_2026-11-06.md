## 3. Host scripts (ExtendScript)

### `host/import.jsx`
- `VB.placeSVG(encodedArgs)` places downloaded SVGs; accepts JSON payload (URI-decoded by caller/host contract).
- SVG import strategy: `groupItems.createFromFile(File)` primary, path fallback, then `placedItems.add()` + `embed()` fallback; keeps linked on embed failure when possible. Handles Illustrator SVG import issues (e.g. `vector-effect`/error 129 cases addressed in project history).
- Places result on target layer (`Vectorizer` by default), fits to bounds/union, selects result, optional hide-original behavior (including batch/current-original handling via batch tags/items).
- Returns structured JSON via `VB.toJSON` with clear error codes (`noDocument`, `docChanged`, `documentLocked`, `fileNotFound`, `fileUnreadable`, `badSvgFile`, `badBounds`, `layerLocked`, `svgImportFailed`, `placeFailed`, `badArgs`, etc.). Includes file-busy retry and SVG header validation.

### `host/common.jsx`
- Provides shared CEP/ExtendScript utilities: `VB.ping/selfTest/toJSON/fromJSON/log`, bridge/temp paths, `ensureBridgeFolder`, command/file helpers, `openUrl/openFolder`, bounds helpers (`itemBox`, `unionBounds`), artboard fitting, doc/editability checks.
- `VB.openFolder(path)` is used by the panel for log and SVG folders.

### `host/agent.jsx`, `host/export.jsx`
- Modified recently (mtimes indicate changes). `agent.jsx` participates in agent/daemon start/stop/status and warm-daemon control; `export.jsx` participates in selection export and batch preparation/export. Review these files directly before changing agent/batch contracts.

## 4. Agent (Node/Puppeteer) — `agent/`

### `agent/daemon.js` (warm Chrome daemon, bounded page pool)
- Keeps headless Chrome and a **pool of reusable pages** on the signed-in vectorizer.ai profile.
- Supports bounded parallel jobs via `--workers` (`1–4`, default logic observed in code).
- Local control/API includes health/status and run handling; jobs write progress/results to per-job status paths so panel polling can track parallel work.
- Pre-warms a page for lower first-run latency; manages page reuse/reset and busy/503 behavior when workers are saturated.

### `agent/daemon-ctl.js`
- Start/stop/control helper for the daemon; accepts worker-related args (e.g. `--workers N`).

### `agent/run.js`
- Job execution/status writing (`writeStatus`/status file handling) used for vectorizer.ai upload → vectorize → download flow; integrates with daemon/page reuse and per-job status paths.

### Operational note
- Warm daemon uses the signed-in Chrome profile; profile locking still matters. Sign-in/install flows must coordinate with daemon/profile state (host-side handling exists; validate after changes).
